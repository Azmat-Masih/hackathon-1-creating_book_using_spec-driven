# API Contracts (Docusaurus Configuration Patterns): Module 4 - Frontend Visibility

**Branch**: `001-module4-frontend-visibility` | **Date**: December 30, 2025 | **Spec**: /specs/001-module4-frontend-visibility/spec.md

## Introduction

In the context of Docusaurus documentation, "API Contracts" are defined by the expected configuration patterns, file structures, and metadata (frontmatter) required for content to be correctly parsed and rendered, especially within the sidebar navigation. This feature focuses on ensuring Module 4 adheres to these implicit "contracts" established by the existing Modules 1-3.

## Key Docusaurus Configuration Patterns

### 1. Sidebar Configuration (`sidebars.ts`)

-   **Purpose**: Explicitly defines the structure, order, and labels of documentation categories and individual pages in the sidebar.
-   **Contract**: Module 4 must be added as a top-level item within the `sidebars.ts` configuration, following the array structure used by existing modules. Its label and position should be consistent.
-   **Example (Conceptual)**:
    ```typescript
    // frontend/sidebars.ts
    const sidebars = {
      docs: [
        'intro',
        {
          type: 'category',
          label: 'Module 1',
          link: {type: 'doc', id: 'module-1/index'},
          items: [
            'module-1/chapter-1-intro-ros2',
            // ... other chapters
          ],
        },
        // ... Module 2, Module 3
        {
          type: 'category',
          label: 'Module 4 - VLA for Humanoid Robots', // Must match index.md title
          link: {type: 'doc', id: 'module-4/index'},
          items: [
            {
              type: 'autogenerated',
              dirName: 'module-4', // Generates sidebar from files in the module-4 directory
            },
          ],
        },
      ],
    };
    export default sidebars;
    ```
    *Note: The actual implementation may use `autogenerated` categories for chapter items, or list them explicitly.*

### 2. Markdown Frontmatter (`.md` files)

-   **Purpose**: Provides metadata for individual Markdown files, influencing their display in the sidebar and page title.
-   **Contract**: Each Module 4 Markdown file (`index.md`, `chapter-X-title.md`) must contain a YAML frontmatter block with:
    -   `id`: A unique identifier (typically derived from the filename).
    -   `title`: The display title for the page/sidebar entry.
    -   `sidebar_position`: (Optional, but recommended for explicit ordering) A numerical value indicating the order within its category.
-   **Example (Conceptual)**:
    ```markdown
    ---
    id: chapter-1-intro-vla
    title: Chapter 1 - Introduction to Physical AI & VLA
    sidebar_position: 1
    ---
    ```

### 3. Category Index File (`_category_.json` - if autogenerated)

-   **Purpose**: When using `autogenerated` sidebars, this file defines metadata for a category (folder), including its label and position.
-   **Contract**: If Module 4 chapters are to be `autogenerated`, a `frontend/docs/module-4/_category_.json` file might be required, specifying the category label and `sidebar_position`.
-   **Example (Conceptual)**:
    ```json
    {
      "label": "Module 4 - VLA for Humanoid Robots",
      "position": 4,
      "link": {
        "type": "generated-index",
        "title": "Module 4 Overview"
      }
    }
    ```

## Validation

Adherence to these configuration patterns will be validated by successfully building the Docusaurus site and verifying Module 4's correct appearance and navigation in the frontend sidebar.
