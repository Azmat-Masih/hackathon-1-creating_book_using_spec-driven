# Tasks: Module 4 - Frontend Visibility (Docusaurus)

**Branch**: `001-module4-frontend-visibility` | **Date**: December 30, 2025 | **Plan**: /specs/001-module4-frontend-visibility/plan.md

## Task Dependencies & Parallel Execution

This section outlines the recommended order of user story completion and identifies opportunities for parallel development.

### User Story Completion Order

1.  **User Story 1 (P1)**: Module 4 Visibility in Sidebar
2.  **User Story 2 (P1)**: Navigating Module 4 Content
3.  **User Story 3 (P2)**: Consistency with Existing Modules

*Note: Some foundational investigation tasks are cross-cutting and are placed in early phases.*

### Parallel Execution Examples

-   **Comparing directory placement and file naming conventions** for Modules 1-3 and Module 4 can be done in parallel.
-   **Inspecting frontmatter metadata** for existing modules and Module 4 can be done in parallel.
-   **Running Docusaurus locally and performing initial visual checks** can start early to identify obvious issues.

## Implementation Strategy

We will use a comparative, non-invasive debugging approach as outlined in the plan. The primary focus is to identify inconsistencies between Module 4 and the successfully rendered Modules 1-3. Tasks will be executed to bring Module 4's configuration in line with established patterns. MVP is achieving basic visibility of Module 4 in the sidebar.

## Phase 2: Foundational Sidebar Analysis

- [ ] T008 Examine `frontend/sidebars.ts` to determine if sidebar is explicitly defined or uses `autogenerated` categories for existing modules.

## Phase 3: User Story 1 - Module 4 Visibility in Sidebar (P1)

Goal: Ensure Module 4 appears as a top-level category in the Docusaurus sidebar.
Independent Test: Visually verify "Module 4" is displayed in the sidebar navigation and can be expanded.

- [ ] T012 [US1] Create `frontend/docs/module-4/_category_.json` based on Module 3's pattern, including `label`, `position`, and `link`.
- [ ] T013 [US1] Ensure `frontend/docs/module-4/index.md` has correct frontmatter (id, title, sidebar_position) aligning with `_category_.json`.
- [ ] T014 [US1] If `sidebars.ts` is explicitly defining top-level categories, add "Module 4" entry to `frontend/sidebars.ts` following existing patterns.
- [ ] T015 [US1] Run Docusaurus build (`npm run build` or `yarn build`) in frontend/ and check for errors or warnings related to Module 4.
- [ ] T016 [US1] Run Docusaurus locally (`npm run start` or `yarn start`) in frontend/ and visually verify Module 4 is visible and expandable in the sidebar.

## Phase 4: User Story 2 - Navigating Module 4 Content (P1)

Goal: Ensure all Module 4 chapter links in the sidebar navigate to the correct content pages.
Independent Test: Click on each Module 4 chapter link in the sidebar and confirm successful page load without errors.

- [ ] T017 [US2] Verify `id` and `title` frontmatter are present and correct for all chapter files in `frontend/docs/module-4/chapter-X-title.md`.
- [ ] T018 [US2] Ensure `sidebar_position` (if used) is correctly set for all chapter files to maintain order in `frontend/docs/module-4/chapter-X-title.md`.
- [ ] T019 [US2] Run Docusaurus locally (`npm run start` or `yarn start`) in frontend/ and click all Module 4 chapter links to validate navigation and check for "Page Not Found" errors.
- [ ] T020 [US2] Inspect browser URLs after navigation to confirm correct routing for Module 4 content.

## Phase 5: User Story 3 - Consistency with Existing Modules (P2)

Goal: Ensure Module 4's ordering, labeling, and routing are consistent with Modules 1-3.
Independent Test: Compare visual presentation and navigation flow of Module 4 with Modules 1-3.

- [ ] T021 [US3] Review the sidebar ordering of Module 4 entries relative to Modules 1-3 in `frontend/sidebars.ts` (if applicable) and visually in the UI.
- [ ] T022 [US3] Confirm Module 4 labels (category and chapter titles) are consistent in style and format with Modules 1-3 by reviewing `frontend/sidebars.ts` and `frontend/docs/module-4/`.
- [ ] T023 [US3] Verify routing paths for Module 4 content (e.g., URL slugs) follow the same patterns as Modules 1-3.
- [ ] T024 [US3] Perform a final visual comparison of Module 4's appearance and behavior against Modules 1-3.
